# kumparan-web-playwright-agent

Playwright + TypeScript tests for **kumparan.com (desktop)** and **m.kumparan.com (mobile)**. They were created with **Playwright Test Agents**: the planner explored the live site, the generator wrote the specs and the healer fixed failures. This is Task C of the kumparan QA Engineer skill test.

## Run the tests

```bash
npm ci
npx playwright install chromium
npm test                 # desktop-chrome + mobile-chrome
npm run test:desktop     # or one platform
npm run report           # HTML report
```

No account is needed. This suite covers guest flows only, because login is protected by Cloudflare Turnstile; logged-in flows are in Task B.

## How the agents were used

1. `npx playwright init-agents --loop=claude --project=desktop-chrome` generated the three agent definitions in `.claude/agents/`, the MCP config `.mcp.json` (`playwright run-test-mcp-server`) and the seed.
2. **Seed** (`tests/seed.spec.ts`): opens the project's site as a guest and waits for the header. It imports `tests/fixtures.ts`, which blocks ads and analytics. Those shift kumparan's layout and intercept clicks, so every generated test inherits the same stable environment.
3. **Planner**: explored desktop (`desktop-chrome`) and mobile (`mobile-chrome`, Pixel 7) and saved `specs/kumparan-desktop.plan.md` and `specs/kumparan-mobile.plan.md`.
4. **Generator**: turned each plan scenario into a spec under `tests/common/`, `tests/desktop/` or `tests/mobile/`.
5. **Healer**: ran the suite and fixed the failures.

**The exact prompts are in [PROMPTS.md](PROMPTS.md).** Every prompt requires:
- `data-qa-id` as the preferred locator (`testIdAttribute: 'data-qa-id'` → `getByTestId`);
- a real assertion for every expected result;
- no hardcoded articles (they rotate);
- never submitting comments or reports, and never touching Turnstile.

## Project layout

```
playwright.config.ts   desktop-chrome (kumparan.com) + mobile-chrome (m.kumparan.com); tests/desktop/** and tests/mobile/** run only on their platform
tests/fixtures.ts      shared test/expect: ad blocking + ad-modal handler
tests/seed.spec.ts     agent seed
tests/common/**        scenarios run on both sites
tests/desktop/**       desktop-only scenarios
tests/mobile/**        mobile-only scenarios
specs/*.plan.md        test plans written by the planner
.claude/agents/*.md    planner / generator / healer definitions (generated by Playwright)
.mcp.json              playwright-test MCP server for the agents
```

## Maintaining the suite

- Add a scenario: run the planner on the new area (same rules as in PROMPTS.md), then the generator. Or write the spec by hand using `tests/fixtures.ts`.
- When a test breaks after a site change, run the healer prompt. Review its diff like any other code change, and reject edits that weaken assertions.
- Stability settings (2 workers, 1 local retry, traces on retry) are explained in Task B's `docs/STRATEGY.md`. They apply here too.

**Review checklist after the run**
- All 18 test titles start with their TC ID.
- Every spec imports `test`/`expect` from `tests/fixtures.ts`.
- `getByTestId` is used wherever a data-qa-id exists. Role or text locators are used only where none exists, and no CSS class is used anywhere. Tag selectors appear in only three cases: `h1` (SEO headings that are hidden on mobile), `a` (a card's link) and `script` (the XSS check).
- No `waitForTimeout`, `networkidle`, `test.only`, `test.skip`, `test.fail` or `test.fixme`.
- Nothing submits a comment or a report, logs in, or touches Turnstile.
